## Findings
### 1. STILL VALID: same-page drawing and textbox edits can lose original AI provenance
- Affected files: `src/aems_pdf_annotator/core.py`
- Verification result: `_replace_drawing_annotation()` and `_replace_textbox_annotation()` still persist `original_source=metadata.get("original_source")` without backfilling from the previous source on first human edit.

### 2. STILL VALID: rectangle annotations are handled in inconsistent coordinate spaces
- Affected files: `src/aems_pdf_annotator/core.py`, `src/aems_pdf_annotator/models.py`, `src/aems_pdf_annotator/contract.py`
- Verification result: the runtime behavior is still split. Read/update paths convert between PDF and PyMuPDF spaces, while several creation paths still pass `annotation.bbox.to_rect()` straight into PyMuPDF.

### 3. STILL VALID: numeric stable IDs can still collide with xrefs in the UI bundle
- Affected files: `web/annotator-ui/src/pdf-preview-modal.js`, `web/annotator-ui/src/pdf-preview-modal/annotation-helpers.js`, `src/aems_pdf_annotator/core.py`
- Verification result: API identifiers are better because numeric stable IDs are prefixed with `id:` for backend calls, but the UI still stores and matches local `data-annotation-request-id` values as `stableId || xref`, so numeric collisions remain possible in the browser layer.

### 4. FIXED: sidebar rerenders can stack listeners on existing elements
- Affected files: `web/annotator-ui/src/pdf-preview-modal/annotation-controller.js`
- Verification result: repeated sidebar listeners are now guarded with `data-listeners-bound` and root binding guards.

### 5. STILL VALID: contract validation only partially supports the rendered-annotations path and still allows edge-degenerate highlights
- Affected files: `src/aems_pdf_annotator/contract.py`
- Verification result: `payload_to_annotations()` now has a `rendered_annotations` branch, but `validate_contract_version()` and the published schema still require `feedback_items`. Also, `_normalized_to_bbox()` still allows zero-width/height highlight strips at page edges.

### 6. New Regression: canceling a sidebar edit can resolve against the wrong page
- Affected files: `web/annotator-ui/src/pdf-preview-modal/annotation-controller.js`
- Why this is a bug: the cancel button handler looks up the annotation using `_currentAnnotationsPage`, but the cancel button itself does not carry a page value even though the rendered sidebar items do.
- Impact: in mixed-page sidebar views, cancel can target the wrong annotation or fail to clean up the intended temporary placeholder.
